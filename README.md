# 盲手 Blinder's Hands

> 一只会自己找角度的手。为视障者设计的桌面主动视觉机械臂系统。

视障者说一句“我牙有点疼，布洛芬还能不能吃”，盲手在桌上找到药盒，用深度相机算出它的位置和朝向，自己规划抓取并拿起来，一边翻转一边寻找印着有效期的那一面，读出日期、判断是否过期，再把药放回原处，最后用一句话告诉他：

> “布洛芬缓释胶囊在有效期内，可以使用，有效期到 2027 年 2 月 28 日。”

人只在开头说一句、结尾听一句。中间的感知、决策和动作，全部由系统自主完成。

---

## 一、我们解决的问题

药盒、食品包装上最要紧的信息，有效期、用法用量、过敏原，往往印在最小、最偏的一面，甚至是瓶底的喷码。

视障者可以用手机拍照识别文字，但前提是**他得先知道该对准哪一面**。看不见，就不知道；对不准，识别就失败，只能一遍遍乱转、乱拍，最后还是去问别人。

关于盲人居家生活的研究反复提到这几类困难：

- **药：** 分不清哪盒是哪种药，读不了说明书上的用量，看不到有效期；
- **东西被挪动、掉落后就找不到**，研究者认为这一点被严重低估；
- **长得一样的瓶子分不清**，比如洗发水和护发素。

这些问题有一个共同点：缺的不是识别能力，而是**找到它、拿起来、把它转到对的那一面**的能力。这一步只有一只手能做，手机做不到。

## 二、盲手能做什么

| 你说 | 盲手做 |
|---|---|
| “布洛芬还能不能吃？” | 找到 → 视觉抓取 → 转着找有效期 → 判断是否过期、是否临期 → 放回 → 告诉你 |
| “降压药一次吃几片？” | 找到 → 抓起 → 转着找用法用量 → 读给你听，并提醒禁忌 |
| “孕妇能不能吃布洛芬？”“这瓶酱油含不含小麦？” | 拿起来找到相关的包装文字 → 用一两句话回答，并念出原文依据 |
| “哪瓶是洗发水？” | 拿起来认 → 告诉你这是什么 |
| “把降压药递给我” | 找到、抓起、确认 → 递到你手边，你说“拿到了”才松手 |
| “我的眼药水在哪？” | 看桌面 → “在您左边、靠近您” → 一句句引导你的手：“往右一点，再往前”→“到了，就在您手下面” |
| “帮我整理一下药箱” | 把桌上的药一样一样拿起来查有效期，全部记下 |
| “有哪些药快过期了？” | 直接回答；打开网页时也会主动提醒 |
| “停！” | 机械臂立刻电子急停 |

## 三、技术核心

### 1. 主动视觉闭环：看到结果，再决定下一步怎么动

```
语音 ─► 意图理解（目标物 + 任务 + 问题）─► 反问确认
                                              │
深度相机 ─► 视觉定位目标物 ─► 物体点云 ─► 位置 / 朝向 / 尺寸 ─► 抓取规划 ─► NERO 抓取
                                              │
   ┌──────────────────────────────────────────┘
   ▼  视角规划器选出最有希望的下一个视角
手眼相机拍照 ─► 端侧文字检测（地瓜 RDK BPU）─► 评估这一面
   ├─ 没有文字                    → 视角规划器跳到离已看过视角最远的地方
   ├─ 文字在画面边缘              → 视角规划器往那个方向转
   ├─ 有文字，但偏了 / 歪了 / 模糊 → 按偏移和倾角计算腕部微调量 → 机械臂微调 → 重拍
   └─ 可以读                      → 云端多模态识别 → 字段校验
                                      ├─ 找到需要的信息 → 判断 → 放回或递给使用者 → 语音播报
                                      └─ 不是要找的信息 → 下一个视角
```

### 2. 端侧文字检测：每一帧都要立刻判断

机械臂每动一下，系统都要马上知道“这一面有没有字、在画面哪里、歪了多少、清不清楚”。这一步跑在**地瓜 RDK 的 BPU** 上（DBNet 类文字检测模型），不调用云端，所以快，断网也能判断。检测结果被量化成四个数，作为闭环的反馈信号：

| 指标 | 含义 | 驱动什么动作 |
|---|---|---|
| 文字占比 | 文字区域占画面的比例 | 太小 → 这一面不是信息面 |
| 中心偏移 | 文字中心相对画面中心的位置 | 偏左右 → 腕部偏航；偏上下 → 腕部俯仰；在边缘 → 视角规划往那边转 |
| 倾角 | 文字行相对水平方向的角度 | 歪了 → 腕部自转 |
| 清晰度 | 文字区域的拉普拉斯方差 | 模糊 → 原地等待重拍（多为停止时的抖动） |

### 3. 两层决策：视角内微调 + 视角间规划

- **视角内微调**（`refine_joints`）：把偏差换算成 NERO 腕部三个关节的转动量，单步限幅，并受官方关节限位约束；转动方向由标定工具自动测出。
- **视角间规划**（`ViewPlanner`）：每个观察姿态沿腕部关节展开成一组候选视角。看到空白面，附近的视角也多半是空白面，就跳到离已看过视角最远的地方；看到文字在画面一侧，就往能把那一侧转过来的方向找。

### 4. 视觉抓取

1. 视觉模型在全局画面中框出目标物；
2. 深度相机把框内的像素反投影成点云，用框外一圈估计桌面高度，分割出高于桌面的物体；
3. 主成分分析得出物体长边方向，算出长、宽、高和顶面中心；
4. 规划自上而下的抓取：夹爪顺着长边、沿短边闭合，开口为物体宽度加 2 厘米；短边太宽时自动转 90 度沿另一边夹；
5. 预抓取点 → 直线下降 → 按设定夹持力夹紧 → 直线抬起。每个目标点都要通过安全工作空间检查；
6. 相机到机械臂的坐标变换由手眼标定工具求出：夹爪夹住 ArUco 标记走 9 个点，用 Kabsch 算法求刚体变换，并报告误差。

### 5. 端云分工：只在值得读的时候才调云端

只有端侧判断“这一面可以读”，才把这一张图送到云端多模态模型（Qwen-VL）做结构化识别，每个任务都有调用上限。识别时会告诉模型“使用者要找的是什么”，照片里有多件物品时以它为准。空白面、歪斜面都不会浪费一次云端调用。

### 6. 理解与判断

- **意图理解：** Qwen-Turbo 从一句模糊的口语里提取目标物、任务、具体问题，以及要不要递给使用者；断网时用规则兜底。
- **日期判断：** 支持“有效期至 / EXP / USE BY”、各种年月日写法，以及“生产日期 + 保质期 N 个月 / N 年”推算；只有年月时按当月最后一天判定；30 天内到期会提醒。
- **药箱记录：** 每次读到有效期都记下来，可以直接回答“哪些药快过期了”，打开网页时主动提醒。

### 7. 安全

- 机械臂默认以 30% 速度运行，并开启 NERO 碰撞保护；
- 网页最上方常驻红色“停”按钮，说“停”也能触发电子急停，急停后必须说“继续”才能接着用；
- 所有关节目标都按 NERO 官方关节限位裁剪，所有抓取点都要通过工作空间检查；
- 递物时，使用者说“拿到了”才松开夹爪；没人接就放回原处。

### 8. 为视障者设计的交互

- 整屏是一个按钮，按住说话，松开结束；
- 用语音回答“是 / 不是”来确认，不用找按钮；
- 开始、成功、失败、递物、引导到达的震动各不相同；
- 过程中播报进度：“转到第 2 个角度”“看到字了，调整一下角度”；
- 支持读屏软件（`aria-live`）。

```

   · 布洛芬在您正前方

   · 转到第2个角度                      → 视角规划直接跳到对面
   · 看到字了，调整一下角度              → 文字歪 28°，腕部自转微调
   · 这一面有字，正在读                  → 云端识别 1 次

使用者：我的布洛芬在哪
盲手：布洛芬在您正前方。要我带您的手过去吗？
使用者：要
盲手：往前，往右。
盲手：往前，往右一点。
盲手：到了，就在您手下面，可以拿了。
```

## 五、硬件与软件

| 部分 | 选型 |
|---|---|
| 机械臂 | 松灵 NERO 七轴机械臂 + AgxGripper 夹爪，官方 SDK `pyAgxArm`（CAN）控制；也兼容 NERO Web 后台 HTTP 接口 |
| 端侧计算 | 地瓜机器人 RDK X5（BPU 运行文字检测） |
| 相机 | 深度相机 Intel RealSense（定位、抓取、引导）+ 手眼相机（读包装文字） |
| 云端模型 | 阿里云 Qwen-VL-Plus（识别、定位、物体清单）、Qwen-Turbo（意图） |
| 交互 | 手机浏览器 Web Speech API |
| 后端 | Python、Flask、OpenCV、NumPy |

## 六、代码结构

| 模块 | 作用 |
|---|---|
| `blinders_hands/intent.py` | 意图理解：7 种任务、具体问题、是否递物 |
| `blinders_hands/vision/text_detector.py` | 端侧文字检测（RDK BPU / OpenCV）与视角评估 |
| `blinders_hands/search.py` | 主动视觉搜索：视角内微调 + 视角间规划 |
| `blinders_hands/grasp.py` | 深度相机、物体位姿估计、抓取规划与执行、手眼标定算法 |
| `blinders_hands/vision/recognizer.py` | 云端识别、目标定位、多目标定位、物体清单 |
| `blinders_hands/dates.py` | 有效期解析与判断 |
| `blinders_hands/inventory.py` | 药箱记录与过期提醒 |
| `blinders_hands/guidance.py` | 引导使用者的手 |
| `blinders_hands/arm.py` | NERO 控制：关节、笛卡尔、夹爪、限速、碰撞保护、急停 |
| `blinders_hands/pipeline.py` | 完整任务编排 |
| `blinders_hands/server.py` + `static/index.html` | 后端接口与无障碍语音网页 |
| `tools/` | 摄像头检测、观察姿态与微调方向标定、手眼标定、命令行任务、单文件生成 |
| `tests/` | 32 个自动化测试：日期、意图、文字检测、位姿估计、抓取规划、视角规划、搜索闭环、药箱、引导、递物、急停、全部接口 |
| `submission/blinders_hands_core.py` | 全部核心功能的单文件版 |

## 七、运行

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
pytest -q                                          # 32 个测试

python submission/blinders_hands_core.py demo      # 模拟运行全部任务，不需要硬件和网络
BH_MOCK=1 python -m blinders_hands.server           # 模拟模式打开 https://localhost:5001
```

接上真机：

```bash
pip install -r requirements-hw.txt                 # pyAgxArm、python-can、pyrealsense2

export DASHSCOPE_API_KEY="..."                     # 阿里云 DashScope
export ARM_BACKEND=can CAN_CHANNEL=can0            # NERO 走 CAN 总线
export DEPTH_CAMERA=realsense                      # 深度相机
export HAND_CAMERA_INDEX=1                         # 手眼相机，先用 tools/check_cameras.py 确认
export DETECTOR_BACKEND=rdk RDK_DET_MODEL=/path/to/text_det.bin   # 在 RDK 上用 BPU 检测

python tools/handeye.py marker                     # 生成 ArUco 标记并打印
python tools/handeye.py calibrate                  # 手眼标定 → config/handeye.json
python tools/calibrate.py views                    # 标定观察姿态 → config/poses.json
python tools/calibrate.py refine                   # 自动测出腕部微调方向
python -m blinders_hands.server                    # 手机打开 https://<IP>:5001
```

部署到地瓜 RDK：见 仓库中的 `rdk/README.md`。AdventureX 2026 的原始版本保存在 仓库中的 `legacy/adventurex_2026/`。

## 名字

“盲手”：眼睛缺席时，一双能被一句话驱动、替人去找、去翻、去确认的手。
